雙庫邊界

  • 訂單庫只寫 order／saga／outbox；帳戶庫只寫 accounts／tcc_reservations。
  • Kafka 是唯一跨庫寫入橋；禁止 XA。
  • 擴增獨立 consumer／relay 時這條邊界不變。
flowchart LR UI["Vue :8093"] --> API["TradeController"] API --> ODB["orderdb"] ODB --> OX["outbox_events"] OX --> K["Kafka"] K --> ADB["accountdb TCC"] ADB --> K K --> ODB

啟動前可讀帳戶是否存在；不得在同一 JDBC 交易寫兩庫。

Saga 流程

  • HTTP 202：訂單 PENDING + Outbox RESERVE_FUNDS。
  • 帳戶 Try 成功後編排再發 CONFIRM_FUNDS。
  • FUNDS_CONFIRMED → 訂單 FILLED／Saga COMPLETED。
sequenceDiagram participant C as Client participant O as Order DB participant K as Kafka participant A as Account TCC C->>O: POST trades O->>K: RESERVE_FUNDS K->>A: Try A->>K: FUNDS_RESERVED K->>O: CONFIRM commanded O->>K: CONFIRM_FUNDS K->>A: Confirm A->>K: FUNDS_CONFIRMED K->>O: FILLED

編排狀態在訂單庫；帳戶不寫 saga_instances。

TCC／補償

  • Try：available → frozen。
  • Confirm：吃掉 frozen；Cancel：frozen 還回 available。
  • forceFail 或餘額不足：帳戶 Cancel／不扣款，訂單補償 FAILED。
stateDiagram-v2 [*] --> TRYING: Try TRYING --> CONFIRMED: Confirm TRYING --> CANCELLED: Cancel CONFIRMED --> [*] CANCELLED --> [*]

TCC 管單資源兩階段；Saga 管跨資源順序與補償。

套件地圖

  • order／account 各有 domain + infrastructure。
  • saga 編排與補償；messaging 接 Kafka。
  • expansion 四介面預留給拆進程。
