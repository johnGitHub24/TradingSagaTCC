# 資料庫設計

> 衝突以主規格為準。規範：EngineeringOS `knowledge/database-design.md`

## 1. 存取鏈

```text
Controller → Service (@Transactional 指定 order 或 account TM) → Repository → 該庫
```

禁止單一事務寫兩庫。

## 2. 資料表

### orderdb

| 表 | 用途 | 重要約束 |
|----|------|----------|
| trade_orders | 訂單 | PK order_id |
| saga_instances | Saga 進度 | PK saga_id |
| saga_steps | 時間軸 | PK id，索引 saga_id |
| outbox_events | **發件匣**（待送 Kafka 的信） | `published_at` NULL＝待發；非 NULL＝已寄出 |

> **發件匣語意：** 與訂單／Saga 同交易寫入＝投遞進匣；`OutboxRelayJob` 定時寄出＝郵差。  
> 詳見 [outbox-發件匣.md](outbox-發件匣.md)。與帳戶庫「預留票」不同庫、不同職責。

### accountdb

| 表 | 用途 | 重要約束 |
|----|------|----------|
| accounts | 餘額 | PK account_id |
| tcc_reservations | TCC **預留票**（帳戶側憑證，非訂單） | PK saga_id（冪等 Key） |

> **預留票語意：** Try 成功寫一列＝發票（available→frozen）；Confirm＝兌票扣款；Cancel＝退票還原。  
> 同一 `saga_id` 重送不再二次扣款。訂單庫看不到此表，只靠 Kafka 事件得知結果。

## 3. Entity 對照

| Entity | 表 | 庫 |
|--------|-----|-----|
| TradeOrder | trade_orders | order |
| SagaInstance | saga_instances | order |
| SagaStep | saga_steps | order |
| OutboxEvent | outbox_events | order |
| Account | accounts | account |
| TccReservation | tcc_reservations | account |

## 4. 環境

| Profile | DB | 設定位置 |
|---------|-----|----------|
| default／test | 雙 H2 mem | `application.yml` `trading.datasource.*` |
| 外接 Kafka | 同上 DB | `trading.kafka.embedded=false` |

種子：`ACC-001` available=100000。
